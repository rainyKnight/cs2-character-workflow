# 通用 CS2 角色转模工作流

人物模型、衣服、耳朵、尾巴、妆容和瞳色来自用户的工程。唯一随工作流提供的角色资产是 [第一人称基础手模](assets/shared-hands/manifest.json)。不以某个人物名字、历史版本、骨骼数量、物理参数或受击框数量作为新项目默认前提。

## 开始工作

1. 读取项目规则、用户选择和输入文件。复制 `assets/new-character.json` 建立项目配置，或运行 `scripts/create_project.py --id <项目ID> --source <用户资产路径> --workspace <独立项目目录>`。它只建立配置，不冒充已经转好模型。
2. 默认 `auto`：当前 Codex 完成各阶段的实际制作、验证和存档并继续。用户要求的暂停点写入 checkpoints，只有这些阶段等用户检查；`needs_authoring` 是由当前 Codex 接着制作，不是把工作交回用户。
3. 按 [阶段合同](references/stages.md) 执行，先明确单位、方向、源骨骼、形态键和材质。把每个角色所需映射/参数写进项目配置或 adapter，不固化进通用技能。
4. 第一人称使用 [共用素手规则](references/firstperson.md)，袖套、腕部衔接及衣服材质随用户角色适配。保持已接受的手部网格、UV 与蒙皮，修改指甲等外观时使用独立材质配置。
5. 稳定流程脚本作为 `command` 阶段注册；开放的建模/绑定工作作为 `agent` 阶段由当前 Codex 处理。每阶段产出具体资产和验证证据后才 record。操作说明见 [执行器](references/runner.md)。

## 制作约束

- 以一个 player VMDL 为目标，共用官方动作与角色自身比例映射；不把按枪械自动换人物模型当默认兼容方案。具体约束、骨架、握点与长度由当前角色决定。
- 发根/耳根/尾根跟随角色，动态段独立；接触代理避免反向影响带蒙皮的主体骨。制作或调整物理时读取 [物理响应调校](references/physics.md)，分别处理弯曲柔软度、回正速度和动作驱动；参数按当前骨长、单位、权重确定。
- hitbox 绑定实际伤害求值姿态，手部可合并为一个球，下肢保留大腿/小腿/脚。数量和局部坐标按当前身体计算；检查服务端与客户端姿态，不把弹孔当成伤害证据。
- 编译资源中的骨骼排序、依赖与 remap 由编译器产生。任何后处理必须适配当前实际资源布局，证明几何和映射一致；不手改骨骼索引/标志，不硬套特定网格数量的装配算法。
- 造型/绑定/持枪稳定后再优化。保留脸、手、轮廓、UV/变形边界，比较真实材质依赖闭包；单套显示开销、所有选项总包和新增选项增量分开计量。
- 检查结果明确区分离线通过、用户游戏通过和待测试。由用户测试时提供候选包、预载、自己套用和 Bot 检查指令；不自行操作游戏。
- 新候选使用独立工作目录、资源名和快照，保留已接受版本。项目资源/工具版本和哈希应记录在项目清单；它们是可追溯信息，不是通用流程分支条件。

## 预留扩展，尚未完成

- **换装**：`request.wardrobe.mode = reserve`。读取 [换装设计](references/wardrobe.md)，保持衣服/耳尾网格、脸/虹膜材质切换边界，记录身体遮挡、袖套、物理联动、共享资源和体积预算。实际游戏内切换 adapter 标记 unimplemented。
- **表情、嘴型与眨眼**：`request.expressions.mode = reserve`。读取 [表情设计](references/expressions.md)，审查并保存源形态键/Morph、面部骨或嘴部网格组，优化时验证变形状态。不能为静态导出统一清空需要保留的表情键；实际控制和语音口型仍未实现。

用户明确要求实现时再建立对应 authoring/编译/运行时 adapter。空模板、项目配置或编译成功本身不代表换装/表情已可用。

## 交付与继续改进

交付一个完整角色包及依赖、项目配置、输入锁、阶段快照、检查报告、测试与恢复命令。读取 [诊断与编译原则](references/invariants.md) 处理真实故障。遇到缺工具/源映射的阶段应明确补齐，不假装任意 FBX 已能零适配自动转换。

局部调整从已接受项目输入另建候选，只复用有哈希与证据的上游成果；由作者明确哪些下游需要重验。运行器管理阶段和文件，不代替 DCC 制作、动画适配或游戏实测。
